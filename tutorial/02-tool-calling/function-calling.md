# Function Calling 的完整闭环

Function Calling 是模型输出结构化调用提案的能力。是否执行、用哪个账号执行、如何校验与保存结果，都由宿主运行时决定。

~~~
工具描述与消息 → 模型 → 调用提案 → 校验与策略 → 工具执行
                   ↑                            ↓
                   └────────── 工具结果 ─────────┘
~~~

它与 ReAct 并不互斥：ReAct 描述根据观察选择动作、再根据结果继续决策的模式；Function Calling 可以承载其中的结构化动作。调试时记录可观察决策与结果，不要求模型暴露私有思维过程。

## 三份数据不能混用

| 对象 | 内容 | 权限 |
|---|---|---|
| ToolDescriptor | 名称、描述、输入 Schema | 模型可见的能力说明 |
| ProposedToolCall | 调用 ID、工具名、参数 | 未执行的提案 |
| ToolResult | 成功或错误、内容、Artifact 引用 | 运行时产生的观察 |

实际类型见 [types.ts](../../examples/learning-agent-runtime/src/types.ts)。Tool Descriptor 不包含访问密钥或可任意执行的函数体。

## 一次调用的检查顺序

1. 工具已注册且属于本次 allowedTools。
2. 参数通过运行时校验，不能只依赖模型遵守 Schema。
3. Policy Engine 允许，或已有与本次动作对应的有效审批。
4. 调用预算与取消状态允许继续。
5. 执行并记录结果；错误也转为结构化观察。
6. 将结果关联原 toolCallId，交回模型继续处理。

模型一次返回多个提案时，仍逐个检查预算与权限；不能把“模型调用次数少”当成“工具调用成本小”。

## 厂商适配器练习

[ModelProvider](../../examples/learning-agent-runtime/src/types.ts) 是教学接口。接入实际 SDK 时，适配器需要转换角色、工具参数、调用 ID、结果消息、拒绝、用量与取消信号；不能直接把教学消息原样发送给所有厂商 API。

固定一次“提出工具 → 收到结果 → 最终回答”的录制轨迹做适配器测试，再运行少量真实调用。验证真实协议消息和用量，明确网络测试需要凭证与费用。

~~~sh
npm run tutorial
npm test
~~~

上述本地命令验证确定性闭环；真实模型接入属于练习。
