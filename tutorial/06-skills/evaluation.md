# Skill 评测：触发与执行分开检查

同一个 Skill 可能“选对了但做错”，也可能“根本没有被选中”。把发现与执行分开评测，才能知道应该改 description、正文还是工具。

| 层次 | 样例 | 指标 |
|---|---|---|
| 触发 | 明确请求、同义表达、不相关请求 | 命中、漏触发、误触发 |
| 依赖 | 工具缺失、权限拒绝、版本不符 | 正确阻断与错误说明 |
| 执行 | 正常输入、缺字段、工具失败 | 步骤与分支符合预期 |
| 产出 | 有证据诊断、无证据判断 | 任务成功率、证据覆盖 |
| 效率 | 同一任务的调用与上下文 | 延迟、调用数、token 与费用 |

## 对比方法

固定模型、工具、数据、权限与运行预算，分别测试不加载 Skill 和加载 Skill。保留独立验证集，多次运行真实模型，报告样本量和失败案例。

ScriptedModel 可证明加载、阻断和执行路径，不能证明 Skill 提高模型准确率。产出质量由规则、任务执行结果或人工 Rubric 检查，模型评审仅作辅助。

## 失败归因

- 没选中：检查描述、候选筛选与上下文。
- 选错：增加反例，收窄适用范围。
- 选对但失败：检查正文步骤、输入与依赖。
- 工具执行失败：修复工具或恢复策略，不靠改写描述掩盖。
- 样例通过但真实请求差：检查过拟合与数据覆盖。

修改后执行整个回归集；只有收益稳定且没有增加误触发或越权行为，才发布新的 Skill 版本。生产发布流程见 [阶段 14](../14-production/README.md)。
