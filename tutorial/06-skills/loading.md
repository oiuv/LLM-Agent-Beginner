# Skill 发现与加载边界

将几百份 Skill 正文全部塞入上下文，既占预算，也会引入互相冲突的指令。分层加载只在需要时提供细节。

## 加载流程

~~~
目录索引（name、description）
  → 候选筛选
  → 检查来源、版本、能力依赖
  → 加载 SKILL.md 正文
  → 按任务需要读取 references / scripts / assets
  → 在运行时权限下执行
~~~

[当前实现](../../examples/learning-agent-runtime/src/skills.ts) 演示索引与惰性 loader，不读取磁盘。后续文件适配器应使用成熟 YAML 解析器，不用正则手写完整 YAML 语法。

## 文件适配器练习

1. 限制允许读取的 Skill 根目录，解析 frontmatter，按 [规范](specification.md) 校验字段。
2. 检查目录名与 name 是否一致，并限制文件大小和相对引用范围。
3. 将标准文件字段转换为内部 manifest；未识别扩展显式处理。
4. 缓存以内容摘要或版本标识为键；运行中的 Run 固定使用已加载版本。
5. 引用按需读取，保留来源；脚本执行交给 ToolExecutor 与沙箱。

读取 references 是补充任务资料，不是授予其中任意指令更高权限。工具输出中出现“加载某个 Skill”也不能直接覆盖宿主的选择与权限。

## 失败路径

无候选时继续普通任务或澄清；多个候选冲突时选择最小适用集合；缺依赖时说明缺口；解析或版本校验失败时拒绝加载并记录原因。

验收应覆盖正常加载、缺依赖、损坏文件、版本不符、越界引用和缓存失效。不要在这些边界没有验证前执行 Skill 中的脚本。
