# 工具与 Skill 怎样被发现

工具描述回答“可以执行哪个动作、需要什么参数”；Skill 描述回答“当前任务适合采用哪套方法”。两种发现可能共用检索组件，但返回的对象和权限处理不同。

## 最小流程

1. 根据用户与租户权限过滤能力目录。
2. 根据任务筛选工具 Schema 与 Skill 元数据。
3. 预算允许时加载选中的 Skill 正文。
4. 检查依赖，把本轮允许的工具提供给模型。
5. 对模型提出的每次调用再次校验权限、参数和审批。

可见性过滤不能代替执行时校验；目录变化、权限收回或伪造工具名都可能发生在调用前。

## 描述怎样写

采用“动作 + 对象 + 触发情境 + 边界”。例如“根据学生提供的错题与作答过程诊断误区；需要区分计算失误和概念错误时使用”。

避免“帮助用户处理任何学习问题”这样无法区分候选的描述。加入常见同义表达，但不要堆砌关键词以抢占无关请求。

## 发现策略

候选少时先用清楚的描述与规则；数量增多后可以接入语义检索或分类器。检索索引的实现见 [Embedding 教程](https://github.com/oiuv/LLM-Embedding-Beginner)，本教程重点检查是否选对能力、是否加载过多上下文、是否保持权限边界。

[当前 SkillRegistry](../../examples/learning-agent-runtime/src/skills.ts) 使用触发词匹配；[ToolRegistry](../../examples/learning-agent-runtime/src/tools.ts) 按 allowedTools 返回描述。这是理解职责的最小实验。

描述优化使用固定正例、相似但不适用的反例和独立验证集，详见 [评测](evaluation.md)。
