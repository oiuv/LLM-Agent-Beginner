# 编写可执行的任务方法

好的 Skill 让 Agent 知道下一步怎样行动、何时停止、怎样检查结果。它不只是介绍产品有什么功能。

以错题诊断为例，正文按以下顺序组织：

1. **触发与输入**：题目、学生作答、课程范围；缺少作答时先收集，不推测过程。
2. **操作步骤**：核对条件 → 定位首个错误 → 分类误区 → 给出下一步练习。
3. **决策分支**：计算失误与概念缺失使用不同指导策略。
4. **约束**：只基于提供的证据；写入学习状态前执行权限与证据校验。
5. **产出**：知识点、误区、证据引用、建议动作。
6. **验收与停止**：每条诊断有证据；无法区分原因时提问；限制无证据的反复分析。

description 负责让任务被正确发现，正文负责具体执行。长资料放 references，确定性处理放 scripts，模板与素材放 assets；主文件保留关键步骤与引用入口。

## 避免重复

通用权限与重试策略由运行时统一维护，Skill 只声明任务特有要求。不要在每个 Skill 复制整套安全提示词，也不要复制另一 Skill 的完整正文。

## 创作练习

选三道正常错题、两道信息不全题、两条不相关请求。先写预期路径，再写 Skill。按 [评测方法](evaluation.md) 检查误触发、漏触发与任务成功，不以正文长度衡量质量。
