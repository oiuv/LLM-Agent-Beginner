# 选择固定工作流还是动态计划

固定工作流适合步骤稳定、验收明确的业务。动态规划适合工具结果会改变路径的任务；它增加模型调用、状态管理和验证成本，不天然优于工作流。

## 用同一案例比较

| 情境 | 合适方式 | 原因 |
|---|---|---|
| 按已有薄弱点生成一份计划 | 固定链 | 输入与步骤已知 |
| 按学生选择进入讲解或练习 | 路由工作流 | 分支有限且可描述 |
| 诊断中发现前置知识缺失 | 动态计划 | 需要插入新步骤并重新估计时间 |
| 每天按既定时间发起复习 | 调度器 | “何时执行”不需要模型持续思考 |

Plan-and-Execute 先形成候选步骤，再由执行器逐步调度。执行器仍检查依赖、权限、预算和成功条件；计划不能直接变成不受限制的工具脚本。

任务较大时可做层次拆分：周目标 → 每日任务 → 当次动作。但每层都需可观察产出，避免不断分解而不执行。

## 重规划记录

重规划保存 planId、version、reason、剩余预算、保留步骤和替换步骤。已经发送的通知、已保存的作业等副作用保留其实际状态，不能随新计划删除。

例如“30 分钟改为 15 分钟”：更新目标约束，保留已完成诊断，重新分配尚未执行的练习；不重复向用户发送相同通知。

## 待实现练习

按 [主章的 Plan/PlanStep 设计](README.md) 实现一个内存计划执行器：

1. 拒绝缺失依赖与依赖环；
2. 只启动依赖完成的步骤；
3. 用户修改时间后创建新版本；
4. 旧版本不能继续提交结果；
5. 用运行结果检查 successCriteria；
6. 无可执行步骤或预算不足时返回明确状态。

先用确定性步骤完成测试，再将一个节点换成模型。不要同时引入持久队列、多 Agent 和计划生成器，否则难以定位失败。
