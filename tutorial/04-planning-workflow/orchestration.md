# 工具编排：依赖、并行与汇合

先画数据依赖，再决定并发。以学习计划为例：

~~~
测验证据 → 诊断目标 ┬→ 分数资源查询 ─┐
                   └→ 方程资源查询 ─┴→ 生成计划 → 验收 → 保存
~~~

两次只读查询互不依赖，可以并行。生成计划依赖完整资源集合，保存依赖验收通过。单 Agent 也可以并行调用工具；增加 Agent 数量不是并行的必要条件。

## 汇合契约

| 分支性质 | 失败处理 |
|---|---|
| 必需输入 | 阻止下游，补查、换来源或请求帮助 |
| 可选增强信息 | 标明缺失，允许降级，但不声称完整 |
| 写操作 | 单独记录提交状态，按幂等键处理重复 |
| 共享配额或互斥资源 | 限制并发或顺序执行 |

Promise.all 会在任一 Promise 拒绝时提前拒绝，但不会自动取消其他操作。Promise.allSettled 能收集全部结果，也不自动提供超时、取消或限流。这些能力属于运行时。

## 可运行实验

[collectResources](../../examples/learning-agent-runtime/src/study-workflow.ts) 并行执行独立读取，返回 resources 与 missing；必需资源缺失时不调用计划模型。

~~~sh
npm test
~~~

测试用共享门闩证明两个查询已同时启动，再让一个失败，检查成功结果与缺失列表。它验证并发关系，不以机器耗时断言性能。

## 待实现练习

为资源查询增加并发上限 2、总截止时间和 AbortSignal。模拟一个查询超时、另一个成功，要求：

- 不启动超过上限的请求；
- 取消传递到实际调用；
- 下游不使用缺失的必需输入；
- 记录每个分支的状态，不把一个错误归为“整体模型失败”。
