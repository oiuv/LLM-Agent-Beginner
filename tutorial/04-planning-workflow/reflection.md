# 反思与目标验收

反思的价值来自可操作的反馈。重复要求模型“再仔细想想”，无法证明错误已被修正。

## 四种“完成”要分别判断

| 层次 | 证据 |
|---|---|
| 模型输出结束 | API 返回完整候选答案 |
| Run 正常结束 | 运行时没有未处理步骤或错误 |
| 本次任务验收通过 | 目标约束与交付物检查通过 |
| 长期学习目标达到 | 多次独立评测与延迟保持证据 |

AgentKernel 在未配置 BeforeFinish 验收 Hook 时只保证运行闭环完成；配置后还会检查所提供的交付契约。它不会自动证明用户掌握了知识。

## 反馈闭环

~~~
候选产出 → 外部检查 → 具体失败原因 → 有限修正 → 再检查
                         ↓
                  预算不足 / 无法验证 → 停止或人工处理
~~~

优先使用 Schema、算术约束、测试结果和业务状态；语义质量可以用版本化 Rubric 与独立评审辅助。模型自评可能重复自身错误，不能作为唯一事实来源。

生成器与评审器可以是不同调用，不必是多 Agent。增加评审前先测净收益：任务成功率增加多少，调用成本与延迟增加多少。
