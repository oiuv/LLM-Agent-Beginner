# 从本地实验到可部署服务

当前 learning-agent-runtime 是进程内实验，没有 HTTP 服务、数据库、认证系统或后台 Worker。部署不能只给它套一个 Dockerfile 就声称具备持久执行能力。

## 先确定运行单元

从模块化单体开始：API 负责接收输入和查询状态，Worker 执行 Job，数据库保存 Thread、Task、审批、Checkpoint 与幂等记录，Artifact 存储保存文件。模型与外部工具通过适配器调用。

如果初期只需要同步任务，可以先不引入队列；需要跨进程恢复或长任务后，再添加持久队列与 Worker。

## 分阶段实现

| 步骤 | 实现内容 | 验证 |
|---|---|---|
| 配置 | 服务身份、密钥引用、模型和工具版本 | 密钥不进入源码、上下文与日志 |
| 状态 | 将内存 Store 替换为数据库 | 重启后记录存在，并发更新不覆盖 |
| 任务 | 持久 Job、租约与 Checkpoint | Worker 被终止后可接管 |
| 副作用 | 调用记录、幂等键与状态查询 | 响应丢失后不重复提交 |
| API | 认证、租户隔离、状态查询与取消 | 用户只能访问自己的任务 |
| 运营 | 指标、审计、备份、告警与回滚 | 可定位失败并恢复数据 |

表中是毕业项目的实现任务，仓库没有提供这些服务的生产启动命令。

## 仓库当前可验证的命令

在根目录运行：

~~~sh
npm ci
npm run test:all
npm run tutorial
npm run tutorial:patterns
~~~

test:all 检查 TypeScript 实验与文档链接，不测试真实模型、数据库、MCP 外部接口或线上部署。MCP 实验的安装与启动命令见 [examples](../../examples/README.md)。

## 故障演练

在自己实现的服务中，分别模拟模型超时、写操作响应丢失、审批等待期间重启、Worker 租约过期、权限撤销。记录 Run、Job、Tool Call 与实际业务结果，确认恢复点和剩余预算。

部署完成还需验证真实环境的配置、连通性、持久化、监控和回滚。一次本地测试通过不等于线上任务已经成功执行。
