# Agent 的上下文与提示设计

提示负责表达任务和约束，运行时负责权限、预算、状态与执行。把两者分开，才能定位“模型没理解”还是“系统没执行”。

## 上下文组装顺序

| 内容 | 来源 | 更新时机 |
|---|---|---|
| 身份、通用行为与输出契约 | 受控配置 | 版本发布 |
| 当前目标、约束和待完成项 | Thread / Task | 用户输入或任务更新 |
| 当前 Skill | 已校验的 Skill 包 | 激活任务时 |
| 相关记忆与证据 | 有权限的存储与检索 | 按需读取 |
| 工具描述 | Registry 与权限过滤 | 每轮决策前 |
| 最近工具结果与反馈 | Executor 与验收器 | 每次动作后 |

外部内容必须带来源并作为数据处理，不能让网页或工具返回值修改系统策略。隐藏工具并不等于撤销执行权限，每次调用还要校验。

## 写清可观察目标

弱目标：“认真规划，给出最佳方案。”

可验证目标：“生成 sessions 数组；覆盖指定知识点；总分钟数不超过可用时间；resourceId 来自提供的目录；缺少必要证据时请求补充。”

程序检查数组、覆盖与时长；相关性、难度和表达质量使用另外的评测。提示可以解释规则，不能替代规则执行。

## 反馈与上下文压缩

反馈应指向具体错误，例如“总计 60 分钟，限制为 30 分钟”，而不是笼统要求更好。

压缩历史时保留当前目标、未完成步骤、已提交副作用、证据来源与尚未解决问题。不要用模型摘要覆盖数据库中的真实状态。大型文件保留引用，按需读取。

## 迭代练习

固定任务集与模型，记录提示版本、配置、输入和最终产出；每次只改一个主要因素，对比成功率、误触发、延迟和费用。失败时先检查缺失上下文、工具结果与校验规则，再改提示。

禁止用更强硬的提示承诺“绝不越权”或“永远正确”；权限由运行时验证，质量由外部任务验收与评测决定。
